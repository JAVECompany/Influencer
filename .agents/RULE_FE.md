# 프론트엔드 규칙

## 폴더와 파일명

- `src/main.tsx`는 React를 마운트하고 전역 스타일을 불러온다. 앱 전체의 구성, 레이아웃과 역할별 화면 연결은 `src/app/`에 둔다.
- 페이지는 `src/features/<page>/screens/<Name>Screen.tsx`에 둔다. 같은 관리자 영역처럼 그룹이 필요한 경우 `features/admin/settlement/screens/AdminSettlementScreen.tsx`처럼 그룹 아래에 페이지 폴더를 둔다.
- 페이지 전용 코드는 페이지의 `components/`, `hooks/`, `utils/`, `types/`, `store/`로 역할에 맞춰 나눈다. 필요한 폴더만 만든다. 페이지 내에서 한 컴포넌트만 사용하는 단순 props 타입과 상수는 해당 파일에 둘 수 있다.
- 여러 페이지에서 쓰는 코드는 `src/shared/` 아래의 `components/`, `hooks/`, `utils/`, `types/`, `store/`로 나눈다. 공통 컴포넌트·훅·유틸은 파일이 하나뿐이어도 해당 기능의 하위 폴더에 배치한다. 예를 들어 `components/content/`, `hooks/privacy/`, `utils/media/`를 사용한다.
- 공통 UI 프리미티브는 `components/ui/` 아래에서 버튼은 `actions/`, 다이얼로그는 `dialogs/`, 입력 요소는 `forms/`에 둔다. 새 파일은 같은 역할의 기존 폴더에 배치하고, 새 역할이 생기면 그 역할을 드러내는 폴더를 만든다.
- UI 컴포넌트 파일은 PascalCase로 작성하고 컴포넌트 이름과 파일명을 일치시킨다. 화면은 `Screen`, 다이얼로그는 `Dialog`처럼 역할이 드러나는 이름을 사용한다. 기본 내보내기는 파일의 단일 컴포넌트에만 사용한다.
- 기능 폴더는 kebab-case를 사용한다. 훅은 `useHomeFeed.ts`, 유틸과 타입은 `globeLayout.ts`, `settlementReport.ts`처럼 camelCase와 의미 있는 이름을 사용한다.
- 필요한 모듈의 경로를 직접 가져온다. `shared/`는 페이지나 앱 조립 계층에 의존하지 않는다. 페이지 전용 코드를 다른 페이지에서 쓰게 되면 실제 공통 책임을 확인한 뒤 승격한다.

## 단일 책임과 상태

- 컴포넌트 파일에는 React 컴포넌트를 정확히 하나만 정의한다. 내보내지 않는 컴포넌트와 함수 내부에서 선언하는 컴포넌트도 각자의 파일에 둔다.
- 긴 화면은 목록, 카드, 폼, 다이얼로그, 요약 영역처럼 독립적으로 읽고 수정할 수 있는 단위로 나눈다. 화면 파일에서 어떤 영역을 조립하고 어떤 상태를 넘기는지 드러나야 한다.
- UI는 렌더링, 접근성, 입력값 전달을 담당한다. React 상태·이벤트·브라우저 생명주기를 묶는 동작은 훅에, React와 무관한 계산·정렬·검증은 순수 유틸에 둔다.
- 입력값이나 모달 상태는 쓰는 컴포넌트 또는 페이지 훅에서 관리한다. 한 페이지의 여러 영역이 함께 쓰는 상태는 필요할 때 페이지 `store/`로 옮기고, 페이지 간 공유 상태는 `shared/store/`의 Zustand 스토어에서 관리한다. 구독 범위가 명확하면 selector를 사용한다.

## Zustand 스토어

- 공통 스토어와 페이지 전용 스토어 모두 `store/<도메인>/` 아래에 배치한다. 파일은 `auth/auth.ts`, `wallet/wallet.ts`처럼 저장할 상태의 이름으로 짓는다. 내보내는 스토어 훅에는 `useThemeStore`처럼 역할이 드러나는 이름을 사용한다.
- `store/`는 상태, 상태 조회와 갱신, 스토어 전용 타입, 영속화 설정과 마이그레이션을 맡는다. 입력 검증, 권한·구매 가능 여부 판정, 배송지 정리, 룰렛 추첨, 레코드 생성은 사용 범위에 맞는 `utils/`에 둔다. UI 이벤트와 화면 흐름은 컴포넌트 또는 훅에서 처리한다.
- 도메인 파일에 데이터 필드만 담은 `IAccountField`, 이를 확장해 액션을 선언하는 `IAccountState`, `IAccountField` 타입의 `initialState`, 독립된 `useAccountStore`를 순서대로 정의한다. Immer 초기화 함수는 `immer((set) => ({ ...initialState, ... }))` 형태로 객체를 바로 반환한다. 초기값을 먼저 펼치고 같은 깊이에 액션을 선언한다.
- 액션 이름은 `updateProfile`, `toggleAccount`, `setData`처럼 동작을 드러내는 동사로 시작한다. 서버 데이터를 조회하는 액션은 `fetch`로 시작한다. 스토어 내부에서는 React 훅 호출 없이 상태 조회와 갱신을 수행한다. 단일 필드나 중첩 필드를 바꿀 때는 `store/zustandTypes.ts`의 `createSetDataImmer` 계열을 우선 사용한다. 범용 `setData`를 제공할 때는 필드 인터페이스로 쓸 수 있는 키를 제한한다. `get()`으로 읽은 상태는 조회에만 사용한다.
- 한 도메인의 관련 필드를 함께 바꿀 때는 한 번의 `set((draft) => { … })`으로 갱신한다. 여러 도메인이 함께 바뀌는 데모 액션은 `store/persistence/demo.ts`의 `updateDemoState`에서 변경을 함께 준비하고, 각 스토어에 반영한 뒤 한 번 저장한다.
- 컴포넌트와 훅은 해당 도메인 스토어에 항상 selector를 전달한다. 하나의 필드는 `useAccountStore((s) => s.accounts)`, 하나의 액션은 `useAccountStore((s) => s.setData)`처럼 고른다. 같은 스토어에서 필드가 둘 이상이면 필드끼리, 액션이 둘 이상이면 액션끼리 각각 `useShallow`로 묶는다. 상태와 액션을 한 객체에 섞거나 `useStore()`로 전체 스토어를 구독하지 않는다.
- `getState()`는 이벤트 콜백처럼 렌더링과 무관한 코드에서 최신값을 읽을 때만 사용한다. 화면에 반영할 값은 selector로 구독한다.
- 브라우저 데모 데이터는 액션을 제외한 필드만 `bamgyeol-demo-v1`에 저장한다. 저장 코드와 마이그레이션은 `store/persistence/`에 둔다. 저장 구조를 바꾸는 작업에서는 버전과 마이그레이션을 검토한다.
- 브라우저 테마 설정은 `shared/store/theme/theme.ts`에서 별도 저장한다. 기본값은 시스템 설정이며 사용자가 선택한 설정은 모든 역할에서 공유한다. 새 테마를 추가하면 선택 목록과 최초 화면에 적용하는 초기화 코드를 함께 갱신한다.

## 이름과 코드 포맷

- 프로젝트에서 선언하는 모든 인터페이스는 `IAccountField`처럼 `I`로 시작한다. 타입 별칭은 `ActionResultType`처럼 `Type`으로 끝난다. 외부에서 가져오는 타입과 제네릭 타입 매개변수는 각자의 이름을 사용한다.
- 일반 함수와 함수 값을 담는 변수에는 `getActiveAccount`, `calculateWheelSegments`, `isProductForSale`처럼 동작이나 판정을 드러내는 이름을 사용한다. React 컴포넌트에는 PascalCase, 훅에는 `use` 접두어를 적용한다.
- 코드를 추가하거나 수정할 때 저장소 루트의 [Prettier 설정](../.prettierrc.json)을 항상 적용한다. 수정 범위에 해당하는 파일에 포맷을 적용한다.
- 들여쓰기는 공백 2칸을 사용한다. TypeScript 문자열은 작은따옴표, JSX 속성 문자열은 큰따옴표를 사용한다. 문장 끝의 세미콜론은 생략하고 파일 끝에 줄바꿈을 둔다.
- 긴 JSX 속성 목록, 여러 줄 렌더링, 긴 구조 분해는 줄을 나눠 읽기 쉽게 배치한다. import는 외부 라이브러리와 로컬 모듈 순으로 배치하고 타입 전용 import에는 `import type`을 사용한다.
- `if`, `else`, 반복문 본문은 한 문장이어도 중괄호로 감싸고 본문을 다음 줄에 쓴다. 조기 반환이나 예외로 끝나는 검사 구간 뒤에는 빈 줄을 두어 이어지는 처리와 구분한다.

## 스타일과 검증

- `src/shared/styles/global.css`는 스타일을 불러오는 진입점으로 사용한다. 공통 색상 토큰은 `src/shared/styles/themes/tokens.css`에 두고 테마별 팔레트는 같은 폴더의 독립 CSS 파일에 둔다.
- 화면의 배경, 텍스트, 강조색은 `bg-surface`, `text-foreground`, `bg-accent`처럼 역할을 나타내는 토큰을 사용한다. 사진과 영상 위에는 대비를 유지하는 미디어 전용 토큰을 사용한다.
- 반복하는 버튼, 필드, 모달은 공통 UI를 재사용하고 페이지 전용 클래스는 해당 컴포넌트에 둔다. 강조색은 화면의 주요 행동이나 선택 상태에 우선 사용한다. 상태를 아이콘이나 스위치로 표시할 때는 접근성 이름과 상태도 제공한다.
- 화면을 나눌 때 역할별 메뉴, 반응형 레이아웃, 키보드 조작, 모달의 포커스와 닫기 동작, 보호 콘텐츠 가림을 보존한다. 일반 열람 화면에는 워터마크를 표시하지 않는다.
- 테스트 작성·실행, 린트, 빌드는 사용자 요청이 있을 때만 수행한다. `npm run build`에는 타입 검사가 포함된다. 변경 사항과 실제 수행한 검증 범위를 [프론트엔드 변경 이력](CHANGELOG_FE.md)에 기록한다.
